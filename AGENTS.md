# Repository Agent Instructions

## Project Goal

Jacklet is a lightweight Go alternative to Jackett: a single-binary Torznab/Newznab-compatible indexer proxy that scrapes torrent sites via YAML-defined rules instead of embedding a JVM or a large plugin runtime. Favor a small footprint and minimal dependencies over feature parity with Jackett's full plugin ecosystem.

Jacklet aims to reuse Jackett's own indexer definitions directly, with full compatibility with Jackett's YAML definition format (as used in [Jackett/Jackett's](https://github.com/Jackett/Jackett) `Definitions/` directory), so existing Jackett indexer definitions can be dropped into `definitions/` without modification.

## Commit Messages & History Hygiene

- **Conventional Commits**: Use `type(scope): concise imperative summary`.
- **Specific Scopes**: Use a specific package or subsystem as the scope when appropriate, for example `fix(scraper): ...`, `feat(torznab): ...`, or `refactor(database): ...`. Omit the scope for genuinely cross-cutting changes, as in `test: ...`.
- **Subject Formatting**: Keep the subject concise, lowercase after the colon, and without a trailing period.
- **Atomic Commits**: Treat one cohesive change and its supporting refactors and tests as one commit, even when it touches multiple packages. Split changes only when they are independently meaningful and leave the repository correct at each boundary.
- **Body Requirements**: For a non-trivial commit, add a body after a blank line and use `-` bullets. Write each bullet as a complete sentence ending with a period.
- **Content Focus**: Use body bullets to describe observable behavior, important implementation or safety details, and relevant test coverage. Do not narrate file-by-file edits.
- **Timestamp Symmetry**: When rebasing, amending, or squashing commits, ensure `GIT_COMMITTER_DATE` matches `GIT_AUTHOR_DATE`.
- **Atomic Buildability**: Ensure every commit compiles and verifies cleanly: run `go build ./...`, `go test ./...`, `golangci-lint run` (config in `.golangci.yml`), `reuse lint`, vacuum against the OpenAPI spec (ruleset in `.vacuum.yml`), and `scripts/check-vacuum-rules.sh`, which checks the project's own rules in `.vacuum.yml` still report their planted violations (commands in `docs/development.md`).

Example:

```text
fix(scraper): handle missing release date on listing page

- Fall back to the torrent detail page when the listing omits a release date.
- Skip entries whose date cannot be parsed instead of aborting the scrape.
- Add coverage for missing and malformed date fields.
```

## Naming Conventions

- Follow standard Go naming: `PascalCase` for exported identifiers, `camelCase` for unexported ones. Use `UPPER_SNAKE_CASE`-style only for environment variable names (`PORT`, `API_KEY`), never for Go identifiers.
- Choose clear, descriptive names based on domain behavior. Avoid ambiguous abbreviations, single-letter identifiers outside small conventional scopes (loop indices, receivers), and names that repeat obvious type information.
- Name booleans with predicates such as `is`, `has`, `can`, `should`, `needs`, or `in` for a scanner's position (`inString`), so a flag reads as a flag where it is branched on. Three surfaces keep a bare adjective or participle instead, each because the name's audience is something other than a Go call site:
  - **Fields an HTML template renders**, and the status values copied field-for-field into them. The admin panel's view structs (`pkg/admin/handlers.go`) are read as `{{ if .Authenticated }}` and `{{ if .Secret }}`, where the prefix is noise in the template and the field name is part of the template's contract rather than of any caller; `scraper.IndexerStatus`'s `Authenticated` and `Scraped` are copied straight into those views and carry the same names so the two sides stay legibly one thing.
  - **Toggles in an `Options` struct**, where a keyed literal already reads as an assertion: `admin.Options{SecureCookies: true}` says what it turns on, while `Options{ShouldUseSecureCookies: true}` says it twice.
  - **Fields whose name is their own wire tag**, PascalCased: `CategoryMapping.Default` (`yaml:"default"`), `SearchPath.FollowRedirect` (`yaml:"followredirect"`), `Field.Optional` (`yaml:"optional"`), `Caps.AllowTVSearchIMDB` (`yaml:"allowtvsearchimdb"`). Every tagged field in `pkg/scraper/definitions.go` is named after its own key, so the struct can be read against a Cardigann definition line for line; prefixing the handful that happen to be booleans would make them the only fields that don't match. This is the wire-format rule below, not an exception to it — "idiomatic Go name" there means PascalCasing the key, not substituting a different word.
  - The exemption is about where a name is *read*, not about avoiding a rename. A bool with no template audience and no wire tag of its own takes the predicate.
- Prefer a typed value (`time.Duration`, not a raw `int` of milliseconds) over embedding units in a name. When a raw numeric can't avoid ambiguity — typically at a JSON/YAML/XML boundary — include the unit in the name (e.g. `sizeBytes`).
- Preserve field names defined by external wire formats — Cardigann's YAML definition schema (`categorymappings`, `legacylinks`, `re_replace`, ...) and the Torznab/Newznab XML attributes — via struct tags rather than renaming the wire format to fit Go idiom. Use idiomatic Go names for the Go-side fields themselves and let the tag carry the external name — which means PascalCasing the external key (`re_replace` becomes `ReReplace`), not renaming the concept, so a struct stays readable against the document it models.
- Reuse established Torznab/Cardigann terminology instead of inventing synonyms for the same concept (no "provider" for something the code already calls a tracker or an indexer). "Tracker" and "indexer" are not synonyms: a **tracker** is the remote site and the definition describing it (`scraper.Tracker`, the `tracker` column, "fetch this tracker's pages"), and an **indexer** is what Jacklet serves to clients, in Jackett's vocabulary (`/api/v2.0/indexers/{id}`, the aggregate indexer). The two meet in sentences like "the aggregate indexer answers from every configured tracker"; a sentence that switches word for the same thing has picked the wrong one.
- **Alphabetical struct fields**: sort a struct's field declarations alphabetically by name, case-sensitive (plain byte order), including unexported fields. When a struct mixes exported and unexported fields, case-sensitive order clusters exported fields first (each block alphabetized internally), matching Go's own convention of leading with a type's public surface — don't fold case to force a single interleaved list. Sort a composite literal's named fields to match when practical. A test table is the one exception to plain byte order: it is grouped into identifier, inputs and expectations (see **Test tables** below). This is a plain ordering rule, not a semantic one — it doesn't override Go requirements like an embedded field needing to come first for promotion, and doesn't apply to enum-style `const` blocks whose order is meaningful (e.g. `iota` sequences). It also doesn't apply where declaration order *is* the wire format: `encoding/xml` emits elements in field order and offers no tag to reorder them, so `torznab.Channel` and `torznab.Item` are declared in the order RSS 2.0 requires them to be serialized. A struct taking this exemption says so in its doc comment.

- **Template markup follows Bootstrap's conventions**: the admin panel's templates order a tag's attributes by [Code Guide](https://codeguide.co/#attribute-order) and CSS properties, in the stylesheet and in `style` attributes alike, by RECESS (`stylelint-config-recess-order`, the order Bootstrap enforces). Both are de facto conventions, the most widely adopted order for each, so a frontend reader recognizes them on sight. Code Guide orders *groups* (class; id, name; data-*; src, for, type, href, value and every attribute it does not name; title, alt; role, aria-*; tabindex; style) and leaves the order within a group to taste, as its own `<link rel="stylesheet" href>` shows. RECESS puts each shorthand before its longhands (`font` before `font-size`, `border` before `border-color`), so following it never lets a shorthand reset a longhand written above it. Custom properties are variables rather than styling and keep whatever order reads best. `TestTemplatesFollowBootstrapOrdering` (`pkg/admin/templates_test.go`) holds the templates to both against `recessOrder`, the subset of RECESS the panel uses, declared beside it; a property the panel starts using fails it until that property is inserted at its position in the package's `groups.js`. A template file declares its `{{define}}` blocks in the order they appear on the page — a layout's skeleton first, then the snippets it shares, in the order a page uses them, such as a table's columns. This is a review convention, not a lint, since the order is a reading of the page rather than of the text.

## Code Comments & Documentation

- **American English**: comments, documentation, test names, assertion messages, and log and error text use American spelling (`color`, `behavior`, `honor`, `canceled`, `labeled`, `license` as a noun, `-ize`). The identifiers the code is built on are already American — Go's `context.Canceled` and `image/color`, CSS's `color` property — so prose in the same spelling never disagrees with the name beside it. Two things keep their own spelling: text quoted from an external source, and a name someone else defines, such as a wire-format key or a third-party identifier. `misspell` (`locale: US` in `.golangci.yml`) enforces the rule for any word standing on its own in a Go file, comments, strings and single-word identifiers alike, but cannot see a word inside a camelCase name such as a test's; those names, Markdown, YAML and templates are held to it in review.

- Default to no comments. Only add one when the *why* is genuinely non-obvious: a hidden constraint, a subtle invariant, or behavior that would otherwise surprise a reader.
- **A declaration's explanation goes above it, not inside it**: a comment that says what a function, type or test is *for* belongs on the line before `func` or `type`, as its doc comment; a comment inside the body belongs to the statement it sits above. The split is what lets a reader learn what something is for without reading it, and it is what `go doc` and an editor's hover show. Tests are declarations too — the reason a test exists goes above `func TestX`, while a note about one step stays beside that step, and a step comment must not be promoted just because it happens to be the body's first line. Where the reason is per-assertion rather than per-test, `require`'s message argument already carries it and no comment is needed.
- Do not narrate bug history in comments — no references to a specific error message, a prior regression, "this used to crash", or how an issue was found and fixed. That narrative belongs in the commit message, not the source; comments rot as the codebase evolves while commit history stays accurate.
- Rely on regression tests, not comments, to prevent a fixed bug from resurfacing. A test that reproduces the original failure is durable; a comment warning "don't do X, it broke before" is not enforced and will be forgotten or contradicted by the next edit.
- Make a comment's explanation self-contained rather than pointing to AGENTS.md or another external doc for the reason. Docs and code can be edited independently and drift out of sync, silently turning "(see AGENTS.md)" into a dead pointer; a reference to another function or type in the same file is fine, since it moves and changes together with the comment.
- This applies beyond source comments: other project documentation (`README.md`, `docs/*.md`) should also explain things in its own words rather than citing "AGENTS.md" or a specific rule by name, for the same reason.
- **Subsystem detail lives in skills**: this file holds the rules every change follows and a short entry per subsystem; the full record of why a subsystem behaves as it does is an Agent Skill in `.agents/skills/<name>/SKILL.md`, the standard's own location, which an agent that looks there loads when a task matches its `description`, and any other agent reads where an entry here names it. A skill opens with `name` and `description` frontmatter and says nothing specific to one agent; it is held to the same rules as the rest of the documentation, and the name check below scans it. A new skill gets an entry here naming it, since that entry is what reaches an agent that does not look in `.agents/skills/`.
- **No hardcoded counts or measured results in documentation**: don't write a figure that was true when you measured it — how many definitions parse, how many tests there are, a benchmark timing, a file or package count, a coverage percentage. It is a record of one run against one snapshot, it goes stale the moment either side changes, and nothing in the build checks it. State the standard the code is held to instead ("every definition in Jackett's repository is expected to parse"), and point at the endpoint, command or output that shows the reader the current figure. The same goes for narrating a past run — what a check caught, what once failed and was fixed — which belongs in the commit message for the same reason bug history does.
- Describe behavior in terms of what it does, not what it used to do or doesn't do relative to some other design (e.g. "there is no single endpoint aggregating results" implies a former or expected alternative). State the actual behavior directly instead of contrasting it against an absent or prior one.

## Build & Test

- **Backend Unit Tests**: Run Go package test suites:
  ```bash
  go test ./...
  ```
- **Static Analysis**: Run `golangci-lint run` (config in `.golangci.yml`, adapted from TorrPlay's), which covers `go vet` plus `gosec`, `gocritic`, `staticcheck`, and other linters.
- **Assertions are `testify/require`**: every test asserts through `github.com/stretchr/testify/require` — no hand-rolled `if got != want { t.Errorf(...) }`, and no mixing `require` with `assert` for the same kind of check. One assertion vocabulary across packages is what lets a reader move between `pkg/scraper` and `pkg/torznab` without re-learning how a failure is reported, and `require`'s messages already name got and want, so a third argument is for the *reason* a check matters ("the stored password was rendered into the page"), not a restatement of the values.
  - **`assert` is the deliberate exception, in two places.** Where a loop is meant to report every failure in one run — `pkg/torznab/openapi_test.go` and `cmd/jacklet/openapi_test.go` walk the whole spec through the shared checks in `internal/routetest` (`AssertDocumented`, `AssertBehavior`), and stopping at the first drift would hide the rest of the work — and where an assertion runs off the test's own goroutine (an `httptest` handler, a `wg.Go` worker), since `require` calls `t.FailNow`, which `testing` only permits on the goroutine running the test. Reach for `assert` for one of those two reasons or not at all.
- **Test Coverage & Regression Prevention**:
  - Accompany every bug fix, refactor, and new feature with dedicated unit tests covering edge cases and error paths.
  - Run package test coverage profiles to verify complete path coverage:
    ```bash
    go test -cover ./...
    ```
- **Documentation name check**: when a change renames, removes or unexports anything, confirm the docs don't still name it. This scans every backticked identifier in `AGENTS.md`, `README.md`, `docs/*.md` and the skills in `.agents/skills/` and reports the ones no longer present in `pkg/`, `cmd/` or `internal/`:
  ```bash
  python3 - <<'EOF'
  import pathlib, re
  files = [pathlib.Path("AGENTS.md"), pathlib.Path("README.md"), *sorted(pathlib.Path("docs").glob("*.md")),
           *sorted(pathlib.Path(".agents/skills").glob("*/SKILL.md"))]
  docs = "".join(f.read_text() for f in files)
  token = re.compile(r"\"(?:\\.|[^\"\\\n])*\"|`[^`]*`|'(?:\\.|[^'\\\n])*'|//[^\n]*|/\*.*?\*/", re.S)
  def strip(path):
      return token.sub(lambda m: "" if m.group()[0] == "/" else m.group(), path.read_text())
  code = "".join(strip(p) for d in ("pkg", "cmd", "internal") for p in pathlib.Path(d).rglob("*.go"))
  names = {n for n in re.findall(r"`([A-Z]\w*(?:\.\w+)?)`", docs) if not n.isupper()}
  stale = sorted(n for n in names if n.split(".")[-1] not in code)
  print("\n".join(stale) or "docs name no missing identifiers")
  EOF
  ```
  Comments are stripped first, so a name kept alive only by a stale comment still counts as gone. They are matched in the same alternation as string and rune literals, and each file is stripped on its own, because a path glob such as `templates/*.html` opens a block comment as far as a bare comment regex is concerned. `pkg/admin` has one in a `//go:embed` line and another in a `ParseFS` argument, so a regex that reaches for the next `*/` on its own runs forward from there and deletes everything up to the next block comment in the tree — every identifier in what it ate then reads as missing. Scanning the literals too means whichever opens first wins, so a `/*` inside a string is read as part of that string rather than as a comment. The literals themselves are kept, so a name that appears only in a struct tag still counts as present. It is a prompt to look, not a gate: prose in backticks (`PascalCase`) shows up as a false positive, and it cannot tell a renamed symbol from a deleted one. Run it after any such change.
- **Invented sample data, never real works**: sample titles in code, tests, fixtures, and documentation must be made up — "Example Release", "Sample Show S01E02", "Test Artist" — not the names of real films, series, albums, books, or the people who made them. Jacklet indexes torrent trackers, so a fixture naming a real, in-copyright work reads as a reference to a specific pirated release rather than as neutral test data, which is not something the project should have committed to it. Invented names are also better test data: they cannot collide with a real result during manual testing, they make an assertion's intent obvious, and they never date.
  - This covers a test's own strings as well as any HTML or JSON fixture captured from a live site: scrub a recorded page before committing it rather than saving the tracker's real listing verbatim.
  - Names that identify software and protocols are not sample data and are expected — Jackett, Cardigann, Sonarr, Radarr, Prowlarr, FlareSolverr, Torznab.
  - Definitions are exempt, and are git-ignored besides: they are upstream data mirrored from Jackett, and a tracker's own `categorymappings` descriptions sometimes name real franchises. Editing one to satisfy this rule would break the compatibility the project exists for. If a definition is ever needed for a test, write a fictional one inline rather than committing a real site's.
  - Non-ASCII coverage still matters (see the Cyrillic case-folding tests), so invent non-ASCII sample titles rather than dropping the coverage: "Тестовый Релиз" makes the same point as a real Russian film title.
- **Test terminology**: use precise testing terms across tests, fixtures, and helpers. These names are load-bearing rather than house style: they carry their established test-double meanings, so a reader who sees one knows what to expect without reading the body. Calling an `httptest.Server` a "mock" sends them looking for call-count assertions that are not there, and calling a canned HTML string "fake" suggests a working implementation stands behind it.
  - **`sample`**: a fed-in value, where it needs separating from the result it produces or from a real value alongside it (`sampleNonUnicodeName` next to `expectedDecodedName`). Most synthetic data is a bare literal that needs no prefix; what those literals may contain is the rule above, not this one.
  - **`test...` / `fixture`**: canned payloads, HTML snippets, and static definition files (`testHTML`, `testDef`, `test-tracker`). `fixture` also carries its xUnit sense, the prepared setup a test runs against: an implementation under test bundled with what seeds or drives it (`panelFixture`, `catalogtest.Fixture`), which is what a variable named `fixture` holds.
  - **`testServer`**: an `httptest.Server` serving canned responses (or descriptive role names such as `site` or `tracker`).
  - **`stub`**: an implementation of an interface that returns fixed, usually empty answers so a test can reach the code under test (`stubRow`). It records nothing and asserts nothing.
  - **`fake`**: reserved exclusively for an in-memory, working implementation of an interface (such as an in-memory store or clock).
  - **`mock`**: reserved exclusively for objects pre-programmed with call expectations that verify method invocations.

  The `test` prefix is always available and is *required* only where a bare name would mislead: where it collides with another value in the same test — `testDef` beside the parsed `def` — or where the plain noun reads as the thing under test rather than as the canned input to it. A descriptive role name (`site`, `tracker`, `page`) is equally good and often says more. So `testServer`, `tracker` and, in a short test that holds only one, `server` are all fine; what the rule rules out is a name that leaves a reader guessing which side of the test they are looking at. This is a review convention, not a lint: it settles the confusing cases and deliberately leaves the clear ones to taste.

  `stub`, `fake` and `mock` are the opposite: they are claims about behavior, so use them only when the definition above holds, and never as a generic label for canned data.

- **Test naming**:
  - Name a test of a single function `TestFunction` and a test of a single type's method `TestType_Method`, capitalizing unexported names, for example `TestSafeNext` or `TestIndexerView_State`.
  - Name a test of an endpoint, flow, or behavior spanning several units with a plain descriptive name, for example `TestTorznabHandlerAcceptsEveryAdvertisedMode` or `TestScraperEncodesFormInTrackerCharset`. Treat HTTP endpoint tests, and scraper tests that drive a scrape through a test tracker, as flow tests.
  - Express scenarios as subtests or table cases with `t.Run` and descriptive lowercase names where they share setup or a table. A scenario that needs its own setup, or reads better as its own function, is named `TestType_Method_Scenario`, or `TestFunction_Scenario` for a function, for example `TestScraper_Download_PresentsTheBrowsersSession` or `TestApplyFilter_DateParse`; a new case joins whichever shape its neighbors already use.
- **Test tables**: a table-driven test declares its cases as an anonymous struct and ranges over them as `tc`. A table that runs each case as a subtest names it with `t.Run`; one that loops without subtests has no identifier, and its inputs and expectations follow the same order below.
  - **The case identifier comes first**, in a table with subtests. The field passed to `t.Run` — usually `name`, sometimes the input itself, such as `in`, `path` or `value` — is the first field of the struct and the first key of every row. It is what a reader scans a table by and what `go test -run` matches, so it leads.
  - **Then the inputs, then the expectations.** After the identifier come the fields a case feeds in, then the fields it expects back, so a row reads as "given this, expect that" — the order the Go community writes tables in. An expectation is named `want`, or `want` plus what it is (`wantErr`, `wantStatus`, `wantRun`), which is also what places it: a field is an expectation exactly when its name begins with `want`. Within each group, fields are alphabetical, in the struct and in every row alike.
  - **Fields sharing a type may share a line** (`struct{ in, want string }`) as long as that order holds; split the line when it cannot, since `in, name, want string` has no way to put the identifier first.
  - **A comment about one case sits at the top of its row**, above the identifier, so it stays with the case when the row's keys are reordered.

## Architecture

- `pkg/scraper`: fetches and parses indexer site pages (definitions in `definitions/*.yml`) into torrent listings, applies Cardigann-style field filters, and maps site categories to standard Torznab categories.
- `pkg/torznab`: exposes scraped results over the Torznab/Newznab-compatible API, reading them through a `torznab.Catalog` and importing no storage package.
- `pkg/database`: persists scraped torrents in SQLite. `Store` satisfies `scraper.Sink`, and the package imports `pkg/scraper` for `scraper.Torrent`, the one shape a scrape produces and a store keeps, and `scraper.Query`, `scraper.ErrNotFound` and `scraper.TrackerStats`, the vocabulary a store is asked in and answers with — the dependency runs from storage to scraper, never back, so `pkg/scraper` imports no SQL and no SQLite driver, and its own tests use an in-memory `fakeStore` where a real store would be an import cycle.
- `pkg/admin`: the web administration panel (`/admin`), server-rendered with `html/template` from templates embedded in the package.
- **`pkg/jacklet` is the one place the shared-storage rule is enforced by types** (`jacklet.New`, `jacklet.Store`, `Stack`): the scraper's `Sink`, the Torznab `Catalog` and the panel's `Store` are handed the same object because `New` takes a single `Store` (`scraper.Sink` plus `admin.Store`) and a single `admin.Config`, and `Options.Scraper.Sink` is refused since `New` sets it. `cmd/jacklet` builds its stack through it, so the binary and an embedder wire identically. `Stack.Routes` also turns the `ServeMux` panic a colliding route causes, whether an API path or the panel's prefix, into the returned error, which is why `run` registers its own fixed paths before calling it. The package imports no storage package, guarded by `TestPackageImportsNoStorage`, and `TestNew_SharesOneSettingsSourceAcrossTheParts` and `TestNew_SharesOneStoreAcrossTheParts` are what fail if a part is ever handed something of its own.

- **`pkg/` is a public library surface**: `cmd/jacklet` is one consumer of `pkg/scraper`, `pkg/torznab`, and `pkg/database`, not the only intended one — another Go program should be able to import them directly to embed indexer scraping without running Jacklet's HTTP server. Give every exported identifier a doc comment (`golangci-lint`'s `revive` `exported` check enforces this) and each package a package-level doc comment. A knob that is deployment-specific rather than part of a tracker definition goes in that package's `Options` struct, reached through a `New…WithOptions` constructor while the plain `New…` keeps the defaults (`scraper.Options`, `torznab.Options`).
- **Model only what is honored**: a definition key gets a struct field only when something reads it. A parsed-but-ignored field reads as support that isn't there — `Response.Attribute` and `ErrorBlock.Path` were both removed for this reason, and `Captcha` is an empty struct because only the block's presence carries meaning. Verify a field is genuinely read by renaming it and checking that `go vet ./...` fails; the `unused` linter cannot see exported fields. The same applies to a status field that nothing sets, which is worse than unused because callers read a value that is always zero.
- **Definition-Driven Scraping**: Keep site-specific selectors and parsing rules in YAML definitions (`definitions/*.yml`) rather than hardcoding them in Go, so new indexers can be added without code changes.
- **No definitions are committed**: `definitions/` and `config/` are git-ignored, along with the database and the built binary. Definitions describe specific third-party sites, are third-party data owned by Jackett's project, and change on their own schedule; `config/` holds tracker credentials in plaintext and must never reach a commit. A missing definitions directory is therefore not an error — `DefinitionStore.Trackers` reports no definitions and `main.go` logs a startup warning naming the directory, since an empty install is the ordinary starting state rather than a fault. Tests must build whatever definitions they need inline (see `loadTestTracker`) and never depend on a file being present in `definitions/`.
- **Logging**: Use the single `*slog.Logger` constructed in `cmd/jacklet/main.go` and passed via constructor injection (`scraper.New`, `scraper.NewDefinitionStore`, `torznab.New`) — don't reach for the `log` package or a new logger instance. The one wrapper is the scraper's own: `scraper.NewWithOptions` wraps the injected logger's handler in `redactingHandler`, which redacts tracker addresses from every error a log line carries, and handing it the logger unwrapped would let a passkey reach the logs. It's a `slog.NewJSONHandler` at the level `-log-level`/`JACKLET_LOG_LEVEL` names, `info` by default: structured JSON on stdout unless `-log-file` names a file — the standard shape (`time`/`level`/`msg` plus attributes) that container runtimes and log aggregators expect, letting the deployment environment own log routing/retention wherever there is one.
- **Always resolve an indexer's id via `scraper.TrackerID(def)`, never `def.ID` directly**: a definition may omit `id` (`TrackerID` falls back to `name`); `DefinitionStore.Find` and the DB queries already account for this. Every place that surfaces an indexer's identity to a caller (`JackettIndexers`, `Results`, error messages) must use the same fallback, or a definition without an explicit `id` is advertised with an empty id, and a client built from the listing asks for a broken `/api/v2.0/indexers//results/torznab`-style path even though the indexer is perfectly reachable by name.
- **Configuration resolves flag, then environment, then default**: `parseSettings` (`cmd/jacklet/flags.go`) gives each flag the matching environment variable as its default, which is where that precedence comes from. `run` works from the resolved `settings`. Each setting carries both spellings: `-admin-prefix`/`JACKLET_ADMIN_PREFIX`, `-base-url`/`JACKLET_BASE_URL`, `-config-dir`/`JACKLET_CONFIG_DIR`, `-contact-email`/`JACKLET_CONTACT_EMAIL`, `-db-path`/`JACKLET_DB_PATH`, `-definitions-dir`/`JACKLET_DEFINITIONS_DIR`, `-flaresolverr-sessions`/`JACKLET_FLARESOLVERR_SESSIONS`, `-flaresolverr-url`/`JACKLET_FLARESOLVERR_URL`, `-log-file`/`JACKLET_LOG_FILE`, `-log-level`/`JACKLET_LOG_LEVEL`, `-magnet-trackers`/`JACKLET_MAGNET_TRACKERS`, `-port`/`JACKLET_PORT`, `-retention-days`/`JACKLET_RETENTION_DAYS`, `-trusted-proxies`/`JACKLET_TRUSTED_PROXIES` and `-user-agent`/`JACKLET_USER_AGENT`. An invalid public URL, contact email, log level, port, retention count, magnet tracker URL, admin prefix, trusted proxy or user agent fails startup, so a typo in a deployment is visible immediately.
- **Credentials have no flag, and can come from a file**: `JACKLET_API_KEY`, `JACKLET_ADMIN_PASSWORD` and `JACKLET_ADMIN_PASSWORD_HASH` are environment-only, listed in `secretEnvOnly` and printed under their own heading by `printUsage`. An argument is readable by every other process on the machine for as long as the server runs, and is kept in shell history — the same reasoning that keeps `jacklet hash-password` reading from stdin. Each also reads a `_FILE` variant (`environment.secret`) naming a file to take the value from, which is how Docker and Kubernetes deliver a secret and keeps it out of the environment, where child processes and `docker inspect` can reach it. Supplying both a credential and its `_FILE` form is an error: ignoring one of two deliberately supplied values is how the wrong password reaches production. A trailing newline is stripped because a file written by `echo` has one; other whitespace is kept, since it may be part of the value. An unset `JACKLET_API_KEY` leaves the indexer endpoints unauthenticated, and logs a startup warning.
- **Environment variables are namespaced**: `environment.get` (`cmd/jacklet/env.go`) reads `JACKLET_<NAME>`. A shared environment is a shared namespace — several services in one compose file, or one `EnvironmentFile=` — so an unprefixed `API_KEY` or `DB_PATH` is liable to be another program's, and a collision on `ADMIN_PASSWORD` silently changes who can sign in.
- **HTTP server hardening**: `main.go`'s `http.Server` sets `ReadTimeout`, `IdleTimeout`, and `ReadHeaderTimeout` in addition to `WriteTimeout` — the last one is deliberately `torznab.ScrapeTimeout + 15s`, not some smaller generic default, since a legitimate slow-but-working search can take up to `ScrapeTimeout` before it has anything to write. If `ScrapeTimeout` ever changes, `WriteTimeout` must move with it.
- **`GET /healthz`**: liveness/readiness probe (pings the database, 200/503) for container/orchestrator health checks — see `healthCheck` in `main.go`.

### Subsystems

Each subsystem's full record is an Agent Skill; the entry here names the rules most easily undone and where the rest is.

- **Scraping** (`pkg/scraper`, `Scraper.Scrape`, `DefinitionStore`): the full record is in `.agents/skills/jacklet-scraping/SKILL.md`; read it before changing how trackers are fetched or definitions loaded. The rules most easily undone:
  - One shared `Scraper` serves every request, since its cookie jar, FlareSolverr sessions and per-tracker backoff only work if they persist.
  - A scrape persists only through its `Sink`, once per page, by the leader of identical concurrent searches; a failing sink does not fail the scrape, and a skipped search returns `ErrThrottled`, never an empty result.
  - A definition's `encoding` applies to the form sent as well as the page read.
  - A tracker address leaves the scraper without its query string or fragment: every error `Scrape` and `Download` return is redacted, the scraper's logger redacts every error it logs, and a new exported method that returns a fetch's error redacts it too.
  - A search follows no redirect unless its path sets `followredirect`, and an empty body is an empty answer, not an outage.
  - A search path is a template whose actions' output is URL-encoded into it, and a `?` it carries starts the query string, as in Jackett.
  - A search path is a GET unless it says `post`, as in Jackett.
  - A search input that renders empty or blank is left out unless the definition sets `allowEmptyInputs`, as Jackett leaves it out.
  - A definition's `requestDelay` is left between the tracker's answer to one request and the sending of the next, across searches, logins and downloads alike, as in Jackett.
  - A response is capped at `defaultMaxResponseBytes`, and exceeding it fails the scrape rather than truncating it.
  - A mirror that answers with no results is not a failure; row links resolve against the page that served them.
  - Every client uses Go's default transport or a clone of it, so the standard proxy variables apply; a definition's pinned certificates are trusted only after the standard verification fails, and only on its own hosts.
  - A definition that parsed before keeps serving its last good version when an edit breaks it, and every parse failure is logged.
  - A renamed tracker answers to the ids its `replaces` lists and uses the settings saved under them until it has its own (`TrackerOverrides`); the old file is read where it is until the panel saves the tracker, which writes the settings under the new id and removes the old files it could read, as Jackett moves them; an id another loaded definition still has stays that definition's and is left out of `replaces`.
- **Cardigann template engine** (`renderTemplate`, `filterRegistry`, `pkg/scraper/filters.go`): the full record is in `.agents/skills/jacklet-cardigann-engine/SKILL.md`; read it before changing rendering, a template variable, a filter or date parsing. Templates are rendered with Go's `text/template`, and both they and the filters follow Jackett's behavior, quirks included, because definitions are written and tested against Jackett. The rules most easily undone:
  - `rewriteCardigannTemplate` is load-bearing: it escapes a regular expression argument's backslashes and rewrites a hyphenated `.Config`/`.Result` key, two shapes Jackett's definitions use that `text/template` would otherwise refuse.
  - Every `.Config` value is a string, a checkbox included (`"True"` or `""`), and `.False` is `""`, because definitions compare against both.
  - `queryParams` matches the field set Jackett builds, since a missing field fails the whole template; a new Torznab parameter is added there too. `.Env` and `.Query.APIKey` are deliberately absent, so a definition cannot read a secret.
  - `.Query.Categories` is what the client asked for and `.Categories` is the tracker's own ids; they are not interchangeable.
  - Paging is the definition's job: there is no page loop.
  - Filters keep Jackett's quirks, and `andmatch` is a row filter that never goes in `filterRegistry`.
  - Zone-less dates are parsed in the local zone.
- **Rows and fields** (`pkg/scraper/rows.go`, `extractFields`, `torrentFrom`): the full record is in `.agents/skills/jacklet-rows-and-fields/SKILL.md`; read it before changing how rows or fields are read. The rules most easily undone:
  - Row and field selectors are templates, rendered before they select, as in Jackett.
  - A definition's CSS selector is adapted to cascadia (`cssSelector`, `findIn`): an attribute value or `:contains` argument AngleSharp accepts unquoted is quoted, `:scope` stands for the row, and a group alternative ending in a relative `:has(~ …)` is supported.
  - A field resolves as Jackett's does: a `:root` selector runs from the document root, a selector the row itself matches selects the row, and only the first match is read.
  - A `case` arm is tested against what the field's selector selects, its value is a template, and a JSON arm is compared as a value.
  - A JSON answer's rows follow `attribute`, `multiple` and `count` as in Jackett, its selectors take Jackett's `:has`/`:not`/`:contains` filters, and a row selector naming a missing key fails the search unless `missingAttributeEqualsNoResults` is set.
  - An XML answer has its own case-sensitive parser; goquery would lowercase element names and empty `<link>`.
  - A standard category name matches only as Jackett spells it (`Console/XBox`), and `caps.categories` counts as mappings ahead of `categorymappings`.
  - A row is filed under every category its `category` and `categorydesc` fields map to, as in Jackett, so `Torrent.Categories` is a list, empty when none maps, and then left out of the Torznab feed but kept in the JSON results, as Jackett keeps it only for an interactive search; a mapping with a `desc` adds the tracker's own custom category, numbered exactly as Jackett numbers it, which only a single indexer's caps list.
  - A field key is its name and its modifiers, split at `|`: `|optional` makes it optional and `|append` adds a title or description to an earlier one, as in Jackett.
  - A required field that does not match drops the row; the external ids, `poster`, `genre` and `description` are never required, as in Jackett.
  - An optional field that comes back empty takes its `default`, rendered without the field's filters.
  - A field whose own template names a variable never set fails, as in Jackett: a required one drops the row, an optional one is empty and takes no default.
  - `torrentFrom` parses numbers leniently as Jackett's `ParseUtil` does, reads a bare size as bytes, stores external ids as digits, and serves the `poster` field as `coverurl`; a new media field lands in `scraper.Torrent`, the schema, the store's columns and `torznab.attributes`.
- **FlareSolverr** (`pkg/scraper/scraper.go`, `scrapeWithFlareSolverr`): the full record is in `.agents/skills/jacklet-flaresolverr/SKILL.md`; read it before changing anything FlareSolverr touches. The rules most easily undone:
  - A tracker uses FlareSolverr only when its own config file sets `flaresolverr: true`, a reserved override rather than a definition setting, which the panel writes itself and keeps when its checkbox is hidden.
  - Each tracker has its own session and a slot admitting one request at a time; the number of sessions is bounded, and only an idle one is evicted.
  - A session is checked against `sessions.list` before every use, because FlareSolverr silently creates a fresh one under a name it has lost.
  - What comes back is the browser's page: a JSON or XML answer has to be unwrapped, and the tracker's status is not visible.
  - A torrent file never goes through FlareSolverr; a download presents the cookies and user agent the browser last held instead.
  - FlareSolverr cannot carry `search.headers` (`warnUncarriedHeaders` says so once per tracker), and it mirrors the definition's HTTP method.
- **Downloads** (`Torznab.Download`, `ServeTorrent`, `Scraper.Download`): the full record is in `.agents/skills/jacklet-downloads/SKILL.md`; read it before changing how a release is downloaded. The rules most easily undone:
  - A torrent file is fetched with Jacklet's own session, capped at `defaultMaxDownloadBytes`, read whole and encoded again with its dictionary keys sorted (`canonicalTorrent`), as Jackett serves it, before anything is sent; a magnet is redirected to rather than fetched.
  - Every request a download makes must name one of the tracker's own hosts, and a torrent file's redirect may neither leave them nor drop from HTTPS to HTTP.
  - The endpoint takes a row id, never a URL, so it cannot be pointed at an arbitrary address.
  - A failed download tells the client only which indexer failed, and the cause, which names the tracker's address, stays in the log.
  - A definition's `download` block is followed as Jackett follows it, from the stored details page to the torrent file or magnet.
  - A magnet is built from a row's info hash only for a public or semi-private tracker, with the operator's announce URLs and none of Jackett's built-in list.
- **Storage** (`pkg/database`): the full record is in `.agents/skills/jacklet-storage/SKILL.md`; read it before changing the store. The rules most easily undone:
  - Every database call takes a context and uses the `…Context` variants, since the pool has one connection and an abandoned query blocks every other request.
  - `database.Open` sets WAL journaling and a busy timeout and caps the pool at one connection; without them concurrent scrapes fail with `SQLITE_BUSY` and drop rows.
  - Name matching goes through `nameMatchClause` and the `unicode_lower` function, never a bare `name LIKE ?`, because SQLite folds case for ASCII only.
  - The schema is never migrated: a change bumps `schemaVersion`, and the answer to an old file is deleting it. Every column is `NOT NULL` with a default.
  - Re-scraping upserts, so a row's counts are refreshed rather than frozen at first sight.
- **Torznab API** (`pkg/torznab`, `Torznab.Routes`): the full record is in `.agents/skills/jacklet-torznab-api/SKILL.md`; read it before changing a route, a handler or a response. The rules most easily undone:
  - The URL space is Jackett's: a new endpoint goes where Jackett puts it, or is labeled as Jacklet's own in `Routes`. Jackett's CouchPotato-era surface is deliberately not served, and the API key is read only from `apikey`, not Jackett's `passkey` alias.
  - The aggregate indexer (`all`) runs one store query across its trackers so paging and totals are global, does not fail when one tracker fails, and answers 503 only when no definition loaded at all.
  - `status:healthy` means no recorded failure, so a tracker nothing has searched yet is healthy, unlike Jackett.
  - The indexer directory and the JSON results are Jackett's shapes key for key, casing included; don't tidy them.
  - Each endpoint kind has its own failure format, and a new failure path uses the `errorWriter` it was handed.
  - A failed scrape falls back to the store, and the XML feed answers 502 only when nothing is stored.
  - A failed search names only the indexer to the client, in the XML feed's 502 and in the JSON results' `Error` alike, and its cause, which names the tracker's address, stays in the log.
  - `t=` accepts both the unhyphenated values clients send and the hyphenated caps names, and every mode the caps advertise must be accepted.
  - A search goes only to the trackers whose advertised caps can answer it, as Jackett's `CanHandleQuery` decides; when none can, the XML feed answers 400 with error 201 and the JSON endpoint answers with nothing.
  - The JSON results endpoint is Jackett's interactive search: it keeps a row filed under no category and reads the request as Jackett's does in `interactiveSearch`, a plain search whatever `t` a client sends, with an episode at the end of the query searched as that season and episode and an IMDb id as an IMDb lookup, sent only to the trackers whose movie search takes one.
  - The handlers read through `torznab.Catalog` and `scraper.TrackerSource`, never a storage package, and `catalogtest.Run` is `Search`'s contract.
- **OpenAPI spec** (`cmd/jacklet/public/openapi.yaml`, served at `/docs`): the full record is in `.agents/skills/jacklet-openapi-spec/SKILL.md`; read it before changing an endpoint, a parameter, a response field or the spec. The rules most easily undone:
  - A new endpoint, query parameter, `t` value, response field, response status, content type or security requirement updates `openapi.yaml` in the same change; `pkg/torznab/openapi_test.go` and `cmd/jacklet/openapi_test.go` fail otherwise, in both directions.
  - The spec's lookup tables are sorted alphabetically, and each schema's `required` lists exactly its properties, while an operation's `parameters:` list is grouped by purpose in the order a person configuring a client reads it.
  - A description is CommonMark, as Scalar renders it: a literal value is a code span, not a quoted string, and a paragraph break is two blank lines in a `>` scalar, since one is only a soft break.
  - vacuum lints the spec against `.vacuum.yml`, its recommended rules plus the project's own, and CI fails on any error, warning or info finding; the rules it cannot see, such as key order and code spans, are held in review.
  - The admin panel is not in the spec: it serves pages to a person, not an API.
- **Admin panel** (`pkg/admin`): the full record is in `.agents/skills/jacklet-admin-panel/SKILL.md`; read it before changing the panel. The rules most easily undone:
  - No admin password means no panel: every `/admin` path is a 404, never an open panel.
  - The panel signs in with a session cookie and checks a CSRF token on every non-GET; `JACKLET_API_KEY` travels in a query string and never authenticates it.
  - A sign-in slot is taken per client address before the password is checked, and `X-Forwarded-For` is read from the right, only from a listed trusted proxy.
  - Anything with a side effect, the live manual search included, is a POST.
  - A stored secret is shown as a mask and never rendered into a page, and submitting the mask back keeps what is stored.
  - Config is written atomically with mode 0600, and saving invalidates the tracker's cached login.

**Still not implemented**: the **top-level** `followredirect`, which in Jackett rewrites the configured site URL when a login test is redirected to another domain — Jacklet answers a moved site with mirror failover instead, and does not rewrite an operator's configuration behind their back.

The template layer itself has no known gap: every template in Jackett's repository is expected to render, including the shapes only Jackett's regex substitution accepts, which `rewriteCardigannTemplate` adapts. Render the whole corpus before and after a change here, rather than reasoning about which gap matters. Also: any Cardigann template variable beyond `.Config`/`.Keywords`/`.Categories`/`.Query`/`.Result`/`.Today`/`.True`/`.False`/`.DownloadUri` (`.Env` and `.Query.APIKey` both deliberately — see above); and CAPTCHA handling (fundamentally hard for a headless service with no UI for a human to solve one, so a definition declaring one is refused outright).
